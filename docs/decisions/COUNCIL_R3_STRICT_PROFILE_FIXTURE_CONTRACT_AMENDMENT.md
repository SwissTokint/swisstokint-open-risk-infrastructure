## PROBLEM

PR #33 merged the bounded strict-profile prerequisite architecture, but
pre-generation review found four unresolved representation questions. Freezing
version-1 fixture bytes before resolving them could create mutually
incompatible consumers or evidence that reproduces an unrelated legacy error.

The missing decisions are:

1. exact per-scenario `allow_partial` invocation;
2. exact nested manifest schemas, order and nullability;
3. an independently reviewed fixture-set root pin outside the self-consistent
   version root;
4. exact-byte checkout and cross-platform filesystem proof boundaries.

## CURRENT_BEHAVIOR

- `verifyPomRxChain()` is the frozen historical v0.1 verifier.
- PR 27 contains one valid control and seven expected-red cases.
- Five two-receipt cases require `{ allowPartial: true }`; omitting it changes
  the observed legacy path to a missing-reconciliation rejection.
- The repository has `core.autocrlf=true` on the observed Windows checkout and
  no fixture-root `.gitattributes` rule.
- No version-1 fixture, manifest, checksum file or root pin exists.
- The isolated fixture worktree remains clean at base `743b808`.

## SECURITY_IMPACT

An ambiguous invocation mode can falsely qualify a vector. An underspecified
manifest permits parser differentials and mutable interpretation. A checksum
root stored only inside the checked set proves no independent pin. Text
normalization, path aliases, ADS or reparse points can make reviewed bytes
differ from verified bytes. Simple lowercase is not Unicode full case folding.

This amendment provides repository-integrity controls only. It does not provide
an external signature, host authenticity, Witness, authorization, audit or
certification.

## COMPATIBILITY_IMPACT

The amendment changes no receipt, canonicalizer, hash domain, receipt hash,
schema, verifier result or expected-red outcome. It freezes how later literal
fixtures reproduce the existing PR 27 evidence. Version 1 is not generated by
this documentation change.

## OPTIONS

### OPTION_A

Generate fixtures now and let the implementation choose missing fields.

Rejected: immutable bytes would precede their interpretation contract.

### OPTION_B

Encode invocation and schema decisions only in test code.

Rejected: this hides normative representation decisions in an implementation
and leaves external consumers without a stable contract.

### OPTION_C

Approve this separate Tier-B amendment before generating bytes. It freezes:

- exact scenario and canary object shapes and order;
- per-scenario `allow_partial`;
- zero-based canonical file indices;
- independent `pins.json` placement outside version `1`;
- exact `.gitattributes` rules;
- a pinned Unicode 17.0 full case-fold data dependency;
- distinct portable pure-validator, Linux filesystem and Windows filesystem
  evidence without claiming unsupported cross-platform CI.

Recommended.

## RECOMMENDATION

Adopt Option C. The later fixture PR must be a mechanical realization of this
contract and the merged parent ADR. Any ambiguity discovered during generation
stops the PR and returns to a versioned amendment; it is not guessed in code.

## TEST_PLAN

The later fixture PR must demonstrate:

1. exact raw manifest parsing with duplicate-key rejection at every object
   depth;
2. exactly eight scenarios in the frozen order and one separately typed canary;
3. exact `allow_partial` reproduction for all eight chains;
4. canonical byte and receipt-hash recomputation through the frozen v0.1 path;
5. exact checksum set equality and independent parent-level root-pin matching;
6. BOM, CR, terminal-newline and semantic-equivalent-byte mutations fail;
7. absolute, drive, UNC/device, ADS/colon, backslash, empty, dot, dot-dot,
   symlink and root-escape paths fail;
8. NFC plus pinned Unicode 17.0 full case-fold collision vectors fail;
9. Linux symlink integration and exact-head Windows junction/reparse/ADS local
   evidence are reported separately;
10. expected-red remains exactly seven vulnerable cases and one valid control.
