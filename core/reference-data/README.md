# POM-RX reference plain-data boundary

This directory owns a small shared **reference-only JavaScript object-boundary primitive** for capturing inert bounded data before security-sensitive code reasons about it.

`captureReferencePlainData()` recursively copies supported scalar, plain-object and dense-array values into frozen snapshots. It rejects Node Proxy wrappers before reflective traversal, rejects getters/setters, symbol keys, custom prototypes, hidden object fields, decorated or sparse arrays, unsafe keys, unsupported values and bounded-resource violations.

Descriptor kind is determined only from the descriptor object's own fields. Missing inherited `get` / `set` properties are never read, so inherited `Object.prototype` accessors cannot rewrite captured descriptor values. Object snapshots use a null prototype, and array elements are installed as own data properties instead of using inherited assignment semantics.

Captured arrays remain JavaScript Array exotic objects (`Array.isArray(snapshot) === true`) with their exact own `length` and indexed values, but they do **not** retain the mutable shared `Array.prototype` as their prototype. At module initialization the reference boundary builds and freezes an isolated, null-prototype method surface from the then-current callable Array built-ins. `values()`, `keys()`, `entries()` and `Symbol.iterator` are reference-owned implementations whose iterator objects have null prototypes and own frozen `next`/iterator methods, so traversal does not depend on either the later shared `Array.prototype` or the shared `%ArrayIteratorPrototype%`. Every captured array is attached to that isolated surface before it is frozen. This prevents later replacement of `Array.prototype[Symbol.iterator]`, ordinary methods such as `join`/`map`, or `%ArrayIteratorPrototype%.next` from rewriting traversal of trusted captured values. Code integrating this reference boundary must therefore not depend on `Object.getPrototypeOf(capturedArray) === Array.prototype` or on later monkey-patching of Array methods.

This helper is intentionally **not** canonicalization, hashing, authorization, trusted time, policy evaluation, Witness, Gate execution or external evidence. It creates no security claim about data provenance or truth; it only prevents later semantic reads from consulting caller-controlled dynamic JavaScript behavior after the snapshot boundary.

Adoption by an existing Core or application module remains an explicit reviewed integration step because each caller still owns semantic validation, tighter field-specific limits and compatibility commitments. The current Node reference runtime and its trusted built-in intrinsics at module initialization remain part of the installation boundary; this helper does not claim resilience to poisoning before module initialization or to a generally compromised JavaScript realm.

Reference limits are deliberately small and deterministic: depth 8, 1,000 total nodes, strings up to 16,384 JavaScript code units, object keys up to 128 ASCII-safe characters and arrays up to 1,000 dense elements. These bounds are implementation/reference limits, not a new POM-RX wire protocol.
